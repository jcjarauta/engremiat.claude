# INC-0016 -- Bot de soporte Telegram: no etiquetar toda incidencia como "Documentación"

## Contexto

`src/TelegramSoporteService.js`. Al crear una INCIDENCIA a partir de un
mensaje de soporte por Telegram, el TIPO se fija siempre a
`'Documentación'` sin mirar el contenido del mensaje -- el catálogo
`TIPO_INCIDENCIA` tiene una categoría genérica `'Otra'` (clave `OTRA`)
pensada exactamente para este caso (mensaje sin clasificar).

Código actual (bloque `guardarFormulario('INCIDENCIA', ...)`, línea ~52):
```
  guardarFormulario('INCIDENCIA', null, {
    NIVEL_INCIDENCIA: 'Cliente',
    CLIENTE_ID: cliente.ID,
    TITULO: 'Soporte vía bot -- ' + cliente.NOMBRE,
    TIPO: 'Documentación',
    PRIORIDAD: 'Media',
    ESTADO: 'Abierta',
    OBSERVACIONES: 'De ' + remitente + ' (' + new Date().toLocaleString() + '): ' + texto
  });
```

## Resultado esperado

Cambiar únicamente el valor de `TIPO`:

```
  guardarFormulario('INCIDENCIA', null, {
    NIVEL_INCIDENCIA: 'Cliente',
    CLIENTE_ID: cliente.ID,
    TITULO: 'Soporte vía bot -- ' + cliente.NOMBRE,
    TIPO: 'Otra',
    PRIORIDAD: 'Media',
    ESTADO: 'Abierta',
    OBSERVACIONES: 'De ' + remitente + ' (' + new Date().toLocaleString() + '): ' + texto
  });
```

## Criterios de aceptación

- Solo se toca el valor de `TIPO` en ese bloque, en `src/TelegramSoporteService.js`.
- No se toca ningún otro campo del mismo objeto ni el resto del flujo.

## Definition of done

1. Cambio hecho en `src/TelegramSoporteService.js`.
2. Mensaje final con el formato ESTADO/RESUMEN/ARCHIVOS/GATES de `.clinerules`.
