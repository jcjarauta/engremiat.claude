# INC-0009 -- CosteService: un precio 0 no debe tratarse como "sin fijar"

## Contexto

`src/CosteService.js`, función `calcularCosteMaterialesEstimado_` (línea 52).
El bloque que calcula `preciosPorMaterial` usa `if (!preciosPorMaterial[pm.MATERIAL_ID] || ...)`
-- como `0` es falsy en JS, un precio de valor 0 se trata igual que "todavía
no fijado", así que cualquier fila posterior lo sobreescribe (rompe la
prioridad de `ES_PREFERENTE`). Más abajo, `if (precio === undefined)` es la
comprobación correcta de "sin precio de referencia" -- pero como el bloque
anterior nunca deja un 0 real almacenado sin pisar, ese caso no se cubre
bien tampoco.

Código actual (líneas 61-66):
```
  var preciosPorMaterial = {};
  listarRegistros('PROVEEDOR_MATERIAL', { ACTIVO: 'SÍ' }).forEach(function (pm) {
    if (!preciosPorMaterial[pm.MATERIAL_ID] || pm.ES_PREFERENTE === 'SÍ') {
      preciosPorMaterial[pm.MATERIAL_ID] = Number(pm.PRECIO_UNITARIO) || 0;
    }
  });
```

## Resultado esperado

Cambiar la condición para que use `hasOwnProperty` en vez de comprobar por
truthiness, así un precio 0 ya fijado no se pisa salvo por un preferente
real:

```
  var preciosPorMaterial = {};
  listarRegistros('PROVEEDOR_MATERIAL', { ACTIVO: 'SÍ' }).forEach(function (pm) {
    if (!Object.prototype.hasOwnProperty.call(preciosPorMaterial, pm.MATERIAL_ID) || pm.ES_PREFERENTE === 'SÍ') {
      preciosPorMaterial[pm.MATERIAL_ID] = Number(pm.PRECIO_UNITARIO) || 0;
    }
  });
```

## Criterios de aceptación

- Solo se toca ese bloque (líneas 61-66) en `src/CosteService.js`.
- No se toca el resto de la función ni `costeDiarioRecurso_`.
